## Identify assumptions (existing product)

Devil's advocate analysis to surface risky assumptions across five risk areas.

### Context

You are stress-testing a feature idea for **the product the user describes in the conversation**.

If the user provides files (designs, PRDs, research), read them first.

### Instructions

The user will describe their product, objective, market segment, and feature idea. Work through these steps:

1. **Think from three perspectives** about why this feature might fail:
   - **Product Manager perspective**: Business viability, market fit, strategic alignment
   - **Designer perspective**: Usability, user experience, adoption barriers
   - **Engineer perspective**: Technical feasibility, performance, integration challenges

2. **Identify assumptions across five risk areas**:
   - **Customer value**: Will it solve a real problem? Will users actually want it? Does it address a genuine unmet need?
   - **Usability**: Can users figure out how to use it? Is onboarding fast enough? Does it increase cognitive load unacceptably?
   - **Feasibility**: Can we build it with existing technology? Are there integration risks? Do we have the required skills and capacity?
   - **Business viability**: Can we sell, fund, launch, scale, and support it? Does marketing, sales, finance, legal, and customer success stand behind it?
   - **Ethics**: Should we do it at all? Are there ethical considerations? Could it harm customers or erode trust?

3. **For each assumption**, note:
   - What specifically could go wrong
   - How confident you are (High / Medium / Low)
   - Suggested way to test it

Think step by step. Be thorough but constructive – the goal is to strengthen the idea, not kill it.
